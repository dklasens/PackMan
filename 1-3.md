# PackMan for Windows — v1.4 Candidates

Fixes, optimisations, and features identified for the next Windows release. File references point into `windows/src/PackMan/`.

## Fix-first items (follow-ups to v1.3)

### 1. One UAC prompt per source, not per package (high value)
The v1.3 fix routes every Chocolatey update through `ElevationBroker.RunAsync`, which spawns a new elevated helper process per invocation (`Services/ElevationBroker.cs:26-38`). Updating 3 choco packages currently means 3 separate UAC prompts. Extend the broker protocol to accept multiple `run` messages over one named pipe so a single elevated helper handles a whole batch. `RunUpdatesAsync` already groups updates by source (`ViewModels/MainViewModel.cs:341`), so most of the plumbing exists.

### 2. README is stale
`README.md:46` still says elevation happens "only when you explicitly retry an update with elevation". Chocolatey updates now always elevate. Correct the wording.

### 3. Skip the broker when already elevated
If PackMan itself is launched as administrator, `ProcessRunner` should run commands directly instead of re-launching through UAC. Check `WindowsPrincipal.IsInRole(WindowsBuiltInRole.Administrator)` in `Services/ProcessRunner.cs:35`.

### 4. Graceful UAC-decline handling
If the user clicks "No" on the UAC prompt, `Process.Start` throws `Win32Exception` 1223 (`ERROR_CANCELLED`), uncaught in `Services/ElevationBroker.cs:38`. Catch it and surface "Elevation was declined" as a cancelled/failed state instead of a raw exception message.

## Speed / optimisations

### 5. Cache probes and capability checks
Every scan re-probes everything: `where.exe` fallbacks, `--version` spawns, npm's extra `node --version` (`Services/NpmSource.cs:29`), and pipx's `pipx list --help` feature sniff on every scan (`Services/PipxSource.cs:20-25`). Python-based tools cost 300-500 ms per process spawn. Cache the resolved `ToolContext` per source (persist it in settings) and only re-probe when a command fails. Expected saving: 1-2 s per scan.

### 6. Parallelise post-update verification
`VerifyAsync` re-runs a full `ScanAsync` per source (`Services/PackageSourceBase.cs:51`), and the per-source groups run sequentially (`ViewModels/MainViewModel.cs:341-427`). Updating winget + choco + npm in one run means 3 sequential full re-scans — and `winget upgrade` / `choco outdated` are the slowest commands in the app. Run the per-source verification scans in parallel.

### 7. Cheaper verification
Instead of a full re-scan after updates, verify individual packages: `npm ls -g <pkg>`, `pip show <pkg>`, `choco list --local-only --exact <pkg>`. Saves seconds per update run.

## Features

### 8. Filter/search box on the updates grid
`PackagesView` already exists (`ViewModels/MainViewModel.cs:29`); add a `Filter` predicate plus a textbox. Small change, real payoff when the update list is long.

### 9. Ignore/pin updates
Per-package or per-version ignore list stored in settings (`Services/SettingsService.cs` has the persistence pattern). Scoop holds are already respected (`Services/ScoopSource.cs:58`); a PackMan-level ignore gives the equivalent for choco/winget/npm/pip/pipx.

### 10. Auto-scan on launch + scheduled background scan
The biggest productivity feature. Persist a setting, scan automatically at startup, optionally run a daily scan and toast when updates are found. Pairs naturally with a minimize-to-tray mode.

### 11. New source: .NET global tools
`dotnet tool list --global` / `dotnet tool update --global <id> --version <v>`. Same shape as the npm source, low effort. PowerShell modules (PSGallery) and VS Code extensions are similar-shaped alternatives.

### 12. Package details
Description/homepage via `winget show`, `choco info`, or the PyPI JSON client already in `Services/PipxSource.cs:93-111`. A context-menu "View package page" is the cheap first version.

### 13. PackMan self-update check
Query the GitHub releases API (an `HttpClient` is already registered in DI, `App.xaml.cs:17`) and surface "a new PackMan version is available" in the status bar.

## Suggested v1.4 scope

- **Core:** items 1-4 (elevation polish), 5-6 (scan/verify speed)
- **Headline feature:** item 10 (auto/scheduled scan) or item 9 (ignore updates)
- **Stretch:** items 8, 11
